# 功能与平台差异

核查日期：2026-11-04。源码基线：宿主 `c768cb12c86e59b60fbc69149013850edce509b0`；本仓首个正式版本 `1.0.0` 已发布。生产 Kotlin 源码逐字节迁移；构建独立化并把公开签名所需 `ktor-client-core` 改为 `api`，新增重试合同回归。

## 分层与 API 边界

只有 `http-core`，没有独立 UI、Kuikly Module 或原生分发包。公共包为 `com.dgtang.live.data.remote`。

| 能力 | Android | iOS | OpenHarmony | 宿主与限制 |
| --- | --- | --- | --- | --- |
| `AppHttpClient`、请求/响应、JSON | commonMain | commonMain | commonMain | 注入 URL、身份、隐私、脱敏日志、业务错误映射 |
| `createHttpClient`、`httpTransport` | Ktor + OkHttp | Ktor + Darwin | Ktor + Curl | `HttpClient`/engine/config/request/response 类型作为公开 API，core 依赖传递 |
| 引擎 factory | `createAndroidHttpClientEngine` | `createIosHttpClientEngine`，`waitsForConnectivity=true` | `createOhosHttpClientEngine` | iOS 首次无线授权期间等待系统联网；联网仍由系统决定；证书兼容见下文 |
| 超时与取消 | 共用期限计时 | 相同 | 相同 | 默认 30,000 ms；准备与传输分别计预算。外部取消继续传播 |
| 重试 | 默认 0 | 默认 0 | 默认 0 | 仅调用方显式确认幂等的请求启用；5xx/网络异常/超时，退避 200–800 ms；4xx、取消与响应解析失败不重试 |
| 拦截器与宿主 hook | 共用 | 共用 | 共用 | 请求按声明顺序，结果逆序；固定原请求 context，普通观察异常交由宿主记录，取消不得吞掉 |
| Multipart 字节/流上传 | Ktor 引擎 | Ktor 引擎 | Ktor 引擎 | 宿主持有文件和权限；组件不打开业务路径、不申请媒体权限 |
| 稳定失败原因 | timeout / TLS / 网络等平台异常映射 | NSError 等平台异常映射 | Curl 超时/连接/证书映射 | 未分类返回 null，不伪造业务错误；HTTP 非 2xx 是正常响应 |
| Client 资源 | `close()` 关闭内部 Client | 相同 | 相同 | 宿主在 owner 结束时关闭；取消单请求不等于关闭共享 Client |

不包含业务认证、会话、隐私同意、品牌配置、缓存、设备文件生命周期、H5 Bridge 或页面导航。公共参数与默认值见源码；迁移不新增通用请求框架。

## 证书兼容开关

`1.1.0` 保留三端工厂原有无参函数与二进制签名，转发 `true`；新增 `validateCertificates: Boolean` 显式重载。显式 `false` 时：Android 对该 OkHttp 引擎同时跳过证书链和主机名校验；iOS 仅接受 `ServerTrust` challenge 的服务端 trust，密码、客户端证书及其他 challenge 仍交系统默认处理；OHOS 的 Curl `sslVerify=false` 同时关闭 peer 与 host 校验。该开关不安装全局信任策略，不改变请求取消、错误映射或 Client 资源所有权。

这会接受过期、自签名及主机名不符证书，失去服务端身份保证；仅供宿主明确启用历史服务兼容，后端证书优化完成后统一恢复默认。TLS 协议、密码套件和系统联网策略仍可能拒绝请求，不能保证任何 HTTPS 地址可用。

[AndroidTlsCompatibilityTest](../http-core/src/androidUnitTest/kotlin/com/dgtang/live/data/remote/AndroidTlsCompatibilityTest.kt) 使用仅测试用途的本地自签名、主机名不符证书，检查默认拒绝与显式允许，并以反射核对原 JVM 无参方法仍存在。独立消费者覆盖三端无参及显式 `false` 的公开签名。本版公开产物的 Mac 独立消费者编译已通过；Linux 消费验证延后，设备行为仍须单独验收。
